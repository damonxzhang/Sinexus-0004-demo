测试提交（Test Submission）
用户在测试提交页面向 Web 服务器 POST 一个表单，Web 后端将测试请求写入数据库，生成一条新的作业（job）记录。表单包含：① 测试选择　② GPU 数目选择（1~8，一般选 2ⁿ）　③ 测试优先级（low/normal/high/critical）　④ 超时设置。选择 high/critical 时需填写理由。
提交新测试作业
同一测试可跑在不同数目 GPU 上；数目越多通常越快。当前安装显卡最多的服务器有 8 块，一般选 2ⁿ 块。
测试开始后运行超过该时间仍未正常结束，Test executor 会强制终止并置为 TIMEDOUT。
作业表（Job list）
作业（job）与数据库记录一一对应。可查看作业列表（已完成 / 未完成），点击完成作业的 log/cmd output 链接查看命令输出；未完成的（running / active）作业可取消，以回收测试资源。

    测试表（Test table，含虚拟测试）
    测试管理系统在显卡上运行各类测试（不同数据集、不同框架、训练/推理等）。其中“虚拟测试（virtual）”用于在真实 GPU 负载之外验证框架与调度流程，不占用实际算力。

    C/S 通信（Test manager ↔ Test executor）
    Client（test executor）与 Server（test manager）之间使用套接字（socket）通信，所有请求/响应均为 JSON 格式。主要消息类型：REGISTER / UNREGISTER / CHECK GPU + RUN JOB / CANCEL JOB / JOB DONE / PING。点击下方场景可模拟消息流。
